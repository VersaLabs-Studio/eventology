## 0b. THE REALTIME AUTH BLOCKER (read before HO-M — this is decided, not open)

`src/lib/supabase/client.ts` returns an **anon-key browser client**. This project uses **better-auth,
not Supabase Auth**, so the browser holds *no* Supabase JWT — `auth.uid()` is NULL on the socket.
A client-side Realtime subscription to an RLS-gated table therefore streams **zero rows**.

This is why HO-M ships a token endpoint (see HO-M §2). Do not "fix" it by disabling RLS, by using
the service-role key in the browser, or by making `event_announcements` public.

### 1. Objective
Make the web app an installable **PWA**, and make **tickets render offline** — the QR must display

### 2. Architecture Decisions (LOCKED — do not deviate)
- **HAND-ROLLED service worker. Do NOT add `next-pwa`, `serwist`, `workbox`, or any PWA
  dependency.** `next-pwa` is unmaintained against Next 16 / App Router and would fight the build.
  Ship a plain `public/sw.js` registered from a small client component. → zero-dep, boundary
- **Caching strategy is explicit, not blanket:**
  - App shell + static assets → cache-first.
  - `/(public)/ticket/[ticketId]` HTML + its ticket JSON → **stale-while-revalidate**, so a

  `qr_version` and a max-age; on reconnect the SW revalidates and evicts on version mismatch. State
  clearly in the UI when a ticket is showing from cache and when it was last synced. → correctness
- **Update flow: `skipWaiting` + an explicit "New version available — reload" prompt.** Never
  silently strand users on a stale build. → UX

## HANDOFF PACKAGE HO-M: Live Event Mode (Realtime)
### For: OpenCode → execute (then code-review → audit)
### Golden Template: `src/app/api/protected/events/[id]/broadcast/route.ts` (existing one-way announce + notification fan-out) · `supabase/migrations/039_event_qa.sql` (RLS + helper-fn style) · `src/lib/supabase/jwt.ts` (the JWT bridge)

### 1. Objective
While an event is happening, show a **live layer**: organizer announcements streaming in real time,
a live check-in count, and a "happening now" state — via Supabase Realtime.

### 2. Architecture Decisions (LOCKED — do not deviate)

**2a. The Realtime auth bridge (the crux — build this FIRST).**
The browser Supabase client is anon-only (`src/lib/supabase/client.ts`) and this app uses
better-auth, so `auth.uid()` is NULL on a browser socket and an RLS-gated Realtime stream yields
nothing. Therefore:
- Add `signRealtimeJWT(profileId)` to `src/lib/supabase/jwt.ts` — **same HS256 / `SUPABASE_JWT_SECRET`
  claims as `signSupabaseJWT` (`sub`, `role: 'authenticated'`, `aud: 'authenticated'`) but with a
  SHORT TTL: `10m`.** Do not reuse the 1h token for the browser.
- Add `GET /api/protected/realtime-token` returning `{ token, expiresAt }` for the session user only.
- In the live hook, call `supabase.realtime.setAuth(token)` **before** `.subscribe()`, and refresh
  ~60s before `expiresAt`, re-calling `setAuth`. → security (short-lived, session-scoped)
- **Do NOT** put the service-role key in the browser, disable RLS, or make announcements public.

**2b. Data + realtime surface.**
- `event_announcements` — host writes, confirmed attendees + host read (RLS via the EXISTING
  `fn_attended` from 043 and `fn_is_event_host` from 039 — **reuse, do not redefine**). → P1
- Realtime is enabled on **`event_announcements` ONLY**. Do NOT add `tickets`, `registrations`, or
  any other table to the `supabase_realtime` publication. → least privilege
- **Live check-in count is polled, NOT realtime** — a lightweight count endpoint on a ~15s interval
  while the live window is open. Putting `tickets` on the realtime publication to get a number would
  expose a high-churn, sensitive table's change stream. → security/cost
- Announcements **enqueue** into the existing notification/push seam by calling the existing
  broadcast path — **consume, do not modify the comms seam.** → boundary
- "Happening now" = `start_date <= now() <= end_date`, computed server-side and passed down; the
  live panel mounts only in that window.

### 3. Schema Specification
`supabase/migrations/049_event_announcements.sql` (**049, not 048**):
```sql
-- Migration 049: live event announcements (Realtime-backed).
CREATE TABLE public.event_announcements (
  id         UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  event_id   UUID NOT NULL REFERENCES public.events(id) ON DELETE CASCADE,
  author_id  UUID NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  body       TEXT NOT NULL CHECK (char_length(body) BETWEEN 1 AND 500),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_announce_event ON public.event_announcements(event_id, created_at DESC);

ALTER TABLE public.event_announcements ENABLE ROW LEVEL SECURITY;

-- Confirmed attendees + the host may read; only the host may write.
CREATE POLICY "ann_select_attendee_or_host" ON public.event_announcements FOR SELECT
  USING (public.fn_attended(event_id, auth.uid())
      OR public.fn_is_event_host(event_id, auth.uid()));
CREATE POLICY "ann_insert_host" ON public.event_announcements FOR INSERT
  WITH CHECK (public.fn_is_event_host(event_id, auth.uid()) AND author_id = auth.uid());

GRANT SELECT, INSERT ON public.event_announcements TO authenticated;

-- 028's default privileges grant anon SELECT on every new table; announcements are
-- attendee-only. Revoke explicitly (defense-in-depth alongside RLS).
REVOKE ALL ON public.event_announcements FROM anon;

-- Realtime: guard the ALTER — this is the FIRST use of the publication in this repo.
DO $$
BEGIN
  IF EXISTS (SELECT 1 FROM pg_publication WHERE pubname = 'supabase_realtime') THEN
    ALTER PUBLICATION supabase_realtime ADD TABLE public.event_announcements;
  ELSE
    CREATE PUBLICATION supabase_realtime FOR TABLE public.event_announcements;
  END IF;
END $$;

-- REPLICA IDENTITY so RLS-filtered realtime can evaluate the row.
ALTER TABLE public.event_announcements REPLICA IDENTITY FULL;
```
> **Note the `author_id = auth.uid()` conjunct** in the INSERT policy — `fn_is_event_host` alone
> would let a co-host forge another host's authorship.

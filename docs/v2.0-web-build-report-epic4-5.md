### 4.2 HO-K — SEO/JSON-LD + Tokenized, Revocable ICS Subscribe Feeds (048_calendar_feed_tokens.sql)
- **Schema (048):** `calendar_feed_tokens` — `profile_id`, `token` (32 random bytes, base64url, UNIQUE), `kind` (`my_events`|`saved`), `revoked` boolean, partial index on active tokens. **Append-only rotation** (rotation = revoke old row + insert new; the token value is never UPDATEd). RLS: own rows only. **`REVOKE ALL … FROM anon`** — the single most important line: a feed token is a bearer credential and 028's default privileges would have made them anon-enumerable (the exact mistake class 041 made for `point_ledger`).
- **SEO surface:** `app/sitemap.ts` (App Router convention, `force-dynamic`): statics + approved events (≤5000, `lastModified` from `updated_at`) + active categories + public collections (≤1000); **DB failure falls back to statics — a DB hiccup cannot 500 the sitemap**. `app/robots.ts`: allow `/`, disallow `/api/ /auth/ /admin/ /org/ /settings/ /my-events/ /profile`, sitemap pointer. `lib/seo/event-jsonld.ts`: schema.org Event emitted on the event detail page, attendance mode derived from 046 `location_type` (Online/Mixed/Offline). OG images for `/discover` and `/collections/[slug]`.
- **ICS dedup:** `lib/calendar/build-ics.ts` — the event→VEVENT mapping was **extracted from the existing `/api/protected/calendar` route** (which now imports it) so the one-off download and the subscribe feed share ONE mapping (package constraint: no duplicated logic). Empty feeds return a minimal valid VCALENDAR (calendar clients reject 0-byte subscriptions). Online events labeled "Online" (no venue fabrication).
- **API:** `GET /api/public/calendar/[token]` — **service-role read of the token table is the single sanctioned service use in this package**; revoked → **410 Gone** (rotation kills the old URL immediately); token never encodes identity; data reads then go through `createAuthedClient(profileId)` so **RLS still applies to the feed contents**. `GET/POST/DELETE /api/protected/me/calendar-feed` — list active tokens / create-or-rotate per kind / revoke per kind (Zod: `calendarFeedTokenCreateSchema`).
- **UI:** `components/settings/calendar-subscribe-card.tsx` — per-kind card with copy / rotate (old URL dies) / revoke; URLs contain no identity.
- **Types/keys:** `entities/calendar-feed-token.ts` (row + create), `CalendarFeedKeys`.

### 4.4 HO-M — Live Mode (049_event_announcements.sql)
- **Schema (049):** `event_announcements` — `event_id`, `author_id`, `body` (1–500 chars), `created_at`; index on `(event_id, created_at DESC)`. RLS: **SELECT** = `fn_attended(event_id, auth.uid()) OR fn_is_event_host(...)` (confirmed attendees + host; everyone else streams zero rows); **INSERT** = `fn_is_event_host(...) AND author_id = auth.uid()` — the `author_id` conjunct is required: host-gate alone would let a co-host forge another host's authorship. `REVOKE ALL … FROM anon` (attendee-only data). **Realtime:** `event_announcements` is the FIRST and ONLY table in the `supabase_realtime` publication (least privilege — no tickets, no registrations); the `ALTER PUBLICATION` is guarded by a DO block (first use in repo); `REPLICA IDENTITY FULL` so RLS evaluates against the full row image.
- **The Realtime auth blocker, solved:** better-auth means no Supabase JWT in the browser → `auth.uid()` is NULL on a raw socket. `signRealtimeJWT` (in `lib/supabase/jwt.ts`, alongside the existing `signSupabaseJWT`) mints a **10-minute HS256** token; `GET /api/protected/realtime-token` (session-gated, `no-store`) serves it; `use-realtime-auth.ts` feeds it to `realtime.setAuth()` **before any subscription** and refreshes ~60s pre-expiry (never tighter than 30s) — setAuth updates live subscriptions without re-subscribing. **RLS still applies over the socket: a signed-in non-attendee receives nothing.**
- **API:** `GET/POST /api/protected/events/[id]/announcements` — GET is the backfill for the live panel (RLS-filtered; non-attendees get an empty list, not an error); POST is host-only with **server-injected `author_id`** and Zod (`announcementCreateSchema`). `GET /api/protected/events/[id]/live-count` — attendee-or-host gated (own-registration read or `fn_is_event_host` RPC); the aggregate count is service-role because an attendee's RLS scope cannot count OTHER attendees' rows (the aggregate itself is non-sensitive).
- **Live window is SERVER-computed:** `isHappeningNow(start_date, end_date)` in the `[slug]` server page → `liveWindow` prop → `LivePanel` mounts only inside the window. No client clock drift, no client-side "is it live yet?" polling.
- **UI:** `live-panel.tsx` (announcements stream, `aria-live="polite"`, `aria-busy` during backfill, `motion-reduce:animate-none` on the live-dot ping), `announce-composer.tsx` (host), `live-attendee-count.tsx`.
- **Hooks:** `lib/hooks/use-live-event.ts` (channel lifecycle: subscribe to INSERTs, status machine `connecting|loading|live|denied|error`, **teardown `removeChannel` on unmount — no leaked channels**), `use-realtime-auth.ts`. Both live in `src/lib/hooks/` per the package spec.
- **Types/keys:** `entities/event-announcement.ts` (row + create), `AnnouncementKeys`, `LiveCountKeys`.

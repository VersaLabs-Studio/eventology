## 2. Conventions Established (the de-facto contract every package follows)

These emerged from the golden templates and are now consistent across all nine packages — audit against these:

1. **Auth flow (every `/api/protected/*` route):** `auth.api.getSession({ headers: req.headers })` → 401 `ErrorEnvelope` if absent → `createAuthedClient(session.user.id)` so RLS resolves `auth.uid()` → Zod parse of body → owner fields **always injected server-side** from the session, never trusted from the client.
2. **Envelopes:** `ErrorEnvelope` / `ListEnvelope` from `@/lib/api` on all list+error responses; Next 16 route params are `Promise<…>` and always awaited.
3. **RLS is authz truth.** Routes do not re-implement ownership beyond what's needed for clean status codes (403 vs 404) and host gates via `fn_is_event_host` RPC. Exceptions are documented per-package (service-context operations).
4. **Factory discipline:** entity reads/writes go through the generic factory handlers (`createDocHandler`, `createCreateHandler`, `createUpdateHandler`, `createDeleteHandler`) and factory hooks (`useList/useDoc/useCreate/useUpdate/useDelete`) wherever the route is a plain entity surface. Event-scoped subresources (QA, media, form-fields, transfers, wallet) follow the HO-B bespoke-route + dedicated-keys pattern.
5. **Query keys:** every feature ships a `*Keys` factory in `packages/config/src/query-keys.ts`; every mutation invalidates `Keys.all()`.
6. **Schema layer:** hand-extended `packages/schemas/src/database.types.ts` (gen-shape) + alias rows in `src/generated/database.types.ts` + Zod entities per table + runtime enum arrays in `enums.ts` + barrel exports in `index.ts`.
7. **i18n:** every user-facing string through `t()` with en+am parity (verified by script each package). Organizer dashboard pages follow the pre-existing house style of raw English strings — new public surfaces are translated.
8. **Premium UI:** Framer Motion entrance on new pages, OKLCH semantic tokens only, existing UI kit (Button/Card/Badge/Tabs/Dialog/Switch/Select).
9. **Never-modified seams:** payments RPC (`create_registration_atomic`, `apply_promo_code`, …), comms orchestrator, AI provider seam — consumed, not altered.

## 8. Flagged for the Brain (found, NOT fixed — out of scope)

### 8.1 ⚠ LIVE BUG — `043_event_media.sql::fn_attended` (highest priority)
The function body reads `WHERE r.event_id = p_event AND r.profile_id = p_user` — `registrations` has **`user_id`**, not `profile_id` (007). Any invocation fails at runtime ("column does not exist"), which means:
- `em_insert_attendee` policy on `event_media` INSERT errors → **attendee photo uploads fail with 500**, and
- anything else calling `fn_attended` (QA votes-to-badges paths, etc.) fails.
Suggested fix (one-liner, needs a migration): `CREATE OR REPLACE FUNCTION public.fn_attended(p_event UUID, p_user UUID) … r.user_id = p_user …`. It also explains why HO-I's join-link gates on a direct registration read instead.

### 8.2 Other flags
- **Rewards tuning:** referral points 200/100 and the `reviewer` badge (wired in the reviews route but not present in the seed catalog) — confirm both.
- **Wallet revocation push:** a revoked serial blocks re-issuance, but real Apple/Google wallets only update via live pass-update web services (post-V2.0, needs keys).
- **Structural secret-in-column risk:** `online_url` safety currently depends on the sanitizer at six call sites. Any future `event:events(*)` embed must remember it — consider a `events_public` view or column-level grants post-V2.0 for structural safety.
- **No event edit UI:** `updateEventSchema` accepts the new location fields, but the organizer app is create-only (pre-existing gap); editing an event's meeting URL is currently API-only.
- **Next 16 deprecation:** `middleware` → `proxy` file convention warning on every build.
- **Pre-existing working-tree noise not from V2.0 packages:** `apps/mobile/*` edits, root `tsconfig.json`, `docs/v2.0-roadmap.md`, `scripts/*.mjs`, `reviews/route.ts` GET handler, locale `greeting`/`rails` keys, `.expo/`. Some files mix pre-existing edits with V2.0 edits (notably `lib/auth/server.ts` — referral + transfer hooks are V2.0; check what else is in that diff).

# Eventology V2.0 — Master Roadmap (Web + Mobile)

> **Thesis:** V1.x made Eventology a *complete transactional ticketing platform*. V2.0 makes it a
> **social-discovery + engagement platform** and unlocks **serious ticketing event types**. The
> transactional table-stakes already exist (tiered tickets, payments, payouts, promo codes,
> sponsors, messaging, AI suite, notifications/push, PostGIS nearby, reviews, saved/follow). The
> moat we have NOT built is the *social/retention graph* — who's going, what friends saved, the
> activity feed, collections, gamification, referrals — the exact layer Luma / Partiful / Posh /
> Meetup win on and Eventbrite lacks. V2.0 builds that moat, then adds the ticketing unlocks
> (transfers, wallet passes, virtual/hybrid, custom registration forms) that open new event
> categories.

**Author:** Brain (Opus 4.8). **Date:** 2026-08-24. **Cycle:** V2.0.
**Boundary:** Brain plans/gates/audits → OpenCode builds. Web handoff ships first (this doc's
companion, `eventology-v2.0-web-handoff.md`) while V1.6 mobile is under manual test; mobile V2.0
handoff follows after 1.6 test closeout.

## 1. Competitor Scan — Best-of-Breed, Mapped to Gaps

| Platform | What they win on | Eventology gap it exposes | V2.0 package |
|---|---|---|---|
| **Luma** | Clean RSVP, personal calendar, curated collections, "subscribe to a calendar/host" | No collections; no host-calendar subscribe | HO-C, HO-K |
| **Partiful** | Social invites, "who's coming", playful RSVP, text reminders | No user social graph; no "friends attending" | HO-A |
| **Posh** | Nightlife social graph, **referrals/affiliates**, **ticket resale**, guestlist | No referrals; no transfers/resale | HO-E, HO-G |
| **Meetup** | Groups, **recurring/series events**, community discussion, RSVP streaks | No recurring; no discussion threads; no streaks | HO-I(series), HO-B, HO-D |
| **Dice** | Waitlist (have), **resale**, **wallet passes**, tight discovery | No transfers/resale; no wallet passes | HO-G, HO-H |
| **Eventbrite** | **Custom registration questions**, order mgmt, transfers, add-to-wallet | No custom forms; no transfers/wallet | HO-I(forms), HO-G, HO-H |
| **Resident Advisor / Fever** | Editorial discovery, "this weekend", saved-based feed, map browse | No discovery hub; no map browse; no editorial | HO-J, HO-C |
| **Bandsintown** | Follow → notify on new events (have org-follow), social proof | Follow exists but no notify-on-new-event + no social proof surfaces | HO-A, HO-M |
| **Eventbrite/Ticketmaster** | **Virtual/hybrid events** + streaming | No online-event support | HO-I(virtual) |
| **All modern** | PWA/offline tickets, gamified profiles, UGC galleries | No PWA/offline; no badges; no post-event galleries | HO-L, HO-D, HO-F |

**Design principle carried through:** we do not copy transactional depth we already have — we add
the **relationship, retention, and shareability** layers competitors use to compound growth, plus
the ticketing modes that open new verticals (conferences → custom forms; virtual → streaming;
resale → nightlife/high-demand).

## 2. Web V2.0 — Feature Set (14 packages / 12+ user-facing features)

Grouped into 5 epics. Full paste-ready specs in `eventology-v2.0-web-handoff.md`. Build order is
top-to-bottom (schema-foundation packages gate their consuming UI).

### EPIC 1 — Social Layer (the moat)
- **HO-A · Social Graph & Activity Feed** — user↔user follow (distinct from organizer-follow),
  "friends attending" on event pages, a personalized **activity feed** ("Sara saved X",
  "Dawit is going to Y"), follow-back, mutual counts. *New tables: `user_follows`, `feed_activities`.*
- **HO-B · Event Q&A / Discussion** — threaded questions on event pages, organizer answers,
  upvotes, pinned answers. Pre-event engagement + reduces DM load. *New: `event_questions`,
  `event_question_votes`.*
- **HO-C · Collections & Curated Lists** — editorial (admin) collections ("This Weekend in Addis",
  "Tech Meetups") + user "My Lists" (public/private), shareable. *New: `collections`,
  `collection_items`.*

### EPIC 2 — Engagement & Retention
- **HO-D · Gamification** — badges (first-event, streaks, explorer, super-host), a points ledger,
  attendance streaks, profile trophy case. *New: `badges`, `user_badges`, `point_ledger`.*
- **HO-E · Referral & Invite Program** — personal referral codes, invite links, reward on first
  attended event, referral leaderboard for organizers (affiliate-style). *New: `referrals`,
  `referral_redemptions`.*
- **HO-F · Post-Event Galleries (UGC)** — attendees upload photos to attended events, organizer
  moderation, reactions; feeds social proof. *New: `event_media`, `event_media_reactions`.*

### EPIC 3 — Serious Ticketing Unlocks
- **HO-G · Ticket Transfers & Resale** — transfer a ticket to another user by email; optional
  face-value resale to waitlist; full audit + QR invalidation on transfer. *New: `ticket_transfers`.*
- **HO-H · Wallet Passes** — Apple Wallet (.pkpass) + Google Wallet passes for tickets, behind a
  new **stubbed `packages/wallet` seam** (live-ready). *New: `wallet_passes`.*
- **HO-I · Virtual/Hybrid Events + Custom Registration Forms** — extend `events` with
  location_type (in_person/online/hybrid), stream/meeting URL (access-gated to ticket holders);
  organizer-defined custom registration questions + attendee answers. *Extend `events`; new:
  `event_form_fields`, `registration_answers`.*

### EPIC 4 — Discovery & Platform Polish
- **HO-J · Interactive Discovery Hub + Map** — a `/discover` hub ("This weekend", "Near you" map
  via existing PostGIS nearby, "Because you follow…", trending), map-browse with clustering.
  *Mostly consume; no schema.*
- **HO-K · SEO, Shareability & Calendar Subscribe** — dynamic OG images per event, JSON-LD
  `Event` structured data, sitemap, and **ICS subscribe feeds** (subscribe to an organizer's or
  your own calendar). *Infra; tiny schema for feed tokens.*
- **HO-L · PWA + Offline Tickets** — installable PWA, service worker, **offline QR ticket access**
  (tickets cached; QR renders without network). *Infra/frontend; no schema.*

### EPIC 5 — Real-Time & Cross-Cutting
- **HO-M · Live Event Mode (Realtime)** — Supabase Realtime: live announcements feed, live
  attendee/check-in count, "happening now" state on event pages. *Consume Realtime; small schema
  `event_announcements`.*
- **HO-N · i18n Fold-Forward + Accessibility (WCAG AA)** — every new string en+am; a11y pass
  (focus, aria, contrast, keyboard) across new surfaces. *Cross-cutting; no schema.*

**Deferred / explicitly OUT of V2.0 web scope** (flag, don't build): live payments (keys/KYC —
Phase 4), multi-currency, reserved-seating charts, native mobile-only features (below), a
dedicated Groups/Communities product (large; candidate for V2.1).

## 3. Mobile V2.0 — Structured Outline (handoff AFTER V1.6 test closeout)

Mobile V2.0 = **parity with web V2.0 social/engagement layer** + **native-only superpowers** the
web can't match. Sequenced; full packages authored once 1.6 testing signs off (and the 2 known
1.6 defects — Reviews-stat 404 and profile/identity sync — are folded in as HO-3.1 first).

**MO-parity (consume the same V2.0 endpoints):**
- MO-A Social graph + activity feed tab (friends attending, follow suggestions).
- MO-B Event Q&A on mobile event detail.
- MO-C Collections + "My Lists" + save-to-list.
- MO-D Gamification trophy case on profile; streak nudges via push.
- MO-E Referral/invite via native share sheet + deep links.
- MO-F Post-event galleries with **native camera/library upload**.

**MO-native (mobile-only moat):**
- MO-G **Native wallet passes** — Apple Wallet / Google Wallet add-to-phone from ticket detail
  (uses HO-H pass seam; native PassKit intent).
- MO-H **Offline tickets** — native secure cache; QR works in airplane mode / dead venue signal.
- MO-I **Live Event Mode** push + realtime announcements; **geofenced "you're here" check-in**
  (build on existing GPS nearby).
- MO-J **Home screen widgets / Live Activities** (next ticket, countdown) — SDK-permitting; flag
  if EAS/managed constraints block, fall back to rich push.
- MO-K Interactive map discovery (native map).

**Mobile constraints (carry V1 rules):** single-React 19.1.0 metro pin; any new native dep must be
SDK-54-aligned + root-deduped and explicitly justified (wallet/map/camera may need vetted deps —
brain approves each before handoff); Expo Go dev now defaults to the Vercel domain (see memory
`eventology-expo-go-runtime-blockers`), so V2.0 endpoints must be **pushed + deployed** to be
testable on-device.

## 4. Cross-Cutting Standards (both platforms, enforced by audit)

- **P1 Schema-First:** every new table ships with RLS (`auth.uid()`-scoped), indexes,
  `authenticated`-only grants (never `anon`), and the full type chain regenerated. Owner-scoped
  join tables follow the proven `036/037` pattern; content tables follow `010_reviews`.
- **P2 Factory Pattern:** TanStack factory hooks (`use-*`) with optimistic toggles + query-key
  invalidation, mirroring existing `use-saved-events`/`use-follows` conventions.
- **P6 Type Safety:** Zod at every boundary; no `any` across the seam.
- **P4 Premium UI:** OKLCH theme tokens, glassmorphism, Framer Motion — new surfaces match the
  existing design system, never generic.
- **Security:** RLS is authz truth; HMAC ticket verification stays server-side; transfers/resale
  must invalidate old QR atomically; wallet/comms/AI/payments seams stay stubbed.
- **i18n (HO-N):** en + am for every new string; folds into each package, not a separate build.

## 5. Sequencing & Ship Plan

**Web (now):** OpenCode builds HO-A → HO-N in order. Brain gates each unit (schema push + RLS
proof + `tsc`/`next build`) before the next; Opus audit on every schema/security-bearing package
(HO-A,B,C,D,E,F,G,H,I,K,M). Bundle UI-only packages (J, L, N) with their epic. After each epic
lands green, push `main` → Vercel redeploy so mobile can later consume it.

**Mobile (after 1.6 closeout):** fold HO-3.1 fixes → gate V1.6 → preview APK → then MO-\* packages
in the same epic order, each consuming the already-deployed web V2.0 endpoints.

**Versioning:** web ships as rolling `v2.0-α.N` per epic; `v2.0.0` tag when EPIC 1–3 are live +
audited. Nothing commits/pushes without explicit approval; brain build-gates first (never trust
"build-clean" claims — verified false twice historically).
